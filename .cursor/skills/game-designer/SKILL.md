# 游戏策划全流程设计

整合腾讯游戏策划课程核心方法论。完整九大职能与细则见 [reference.md](reference.md)。

本仓库落地时同时对照 `.cursor/skills/oyster-sim-dev/SKILL.md` 与 `.cursor/rules/oyster-sim-facts.mdc`（技术边界、存档相容、文案语气）。

## 何时启用

- 新模式／玩法（含死鬥）、核心循环、反馈与心流
- 战斗手感（3C、打击感、关键帧）、关卡／动线／掩体节奏
- 数值／经济／掉落／养成平衡
- 文案、世界观、角色台词、IP 边界
- 写策划案、拆需求、评估管线成本

## 工作顺序（先想清楚再改代码）

1. **发现需求**：玩家痛点／体验空洞／商业或内容目标——拆到本质，勿用战术勤奋掩盖战略懒惰  
2. **KES**  
   - **K**：一句话核心亮点（电梯稿）  
   - **E**：自上而下扩展系统与内容  
   - **S**：成本、标准、可实现方式  
3. **核心循环**：核心行动 → 目标与挑战（心流） → 即时反馈（奖励回路）  
4. **策划案**（若改动跨系统或需对齐）：背景概述 → 详细模块 → 风险备注  
5. **落地**：小步验证手感／数值；分阶段验收；同步变更  

## 九大职能速查（选型用）

| 角色 | 你要解决的问题 |
|------|----------------|
| 系统 | 入口、大厅、模式架构、UI 优先级 |
| 玩法 | 核心行动、挑战、反馈 |
| 战斗 | 3C、动作验收、打击感、关键帧 |
| 数值 | 经济／养成／战斗公式／生态节奏／玩法参数 |
| 关卡 | 分区、动线、白模验证、节奏情绪 |
| 文案 | 世界观七件套、叙事、角色、落地文案三标准 |
| 技术策划 | 管线、原型、降本增效（不直接「更好内容」） |
| 世界观／IP | 内容性、确定性、情感性 |
| 主策划 | 串联全局、优先级、落地 |

细节与能力模型见 [reference.md](reference.md)。

## 对 oyster-sim／死鬥的落地检查

改玩法或场景前自问：

- [ ] **K** 是什么？（例：蚵寮工地互丢蚵壳的近距乱斗）  
- [ ] 核心行动是否每 1–3 秒可执行并有反馈？  
- [ ] 挑战节奏：安全区／对峙／交火／补给（蚵堆）是否分明？  
- [ ] 反馈：命中、爆头、挡伞、击杀播报、音效是否即时？  
- [ ] 数值：弹药、伤害部位、复活无敌、移动是否形成可学循环？  
- [ ] 关卡：掩体密度、门洞视线、外景是否服务可读性而非堆砌？  
- [ ] 文案／语气是否仍是台式蚵寮，而非通用竞技场？  
- [ ] 实现是否落在 `src/deathmatch.ts`／既有 WebAudio／不碰存档索引硬约束？  

## 策划案最小模板

```markdown
# 标题（直接说意图）

## 迭代记录
- v0.1：…

## 需求背景与概述（200–300 字）
为什么做、怎么做、成功长什么样。

## 详细描述
### 模块 A
规则／流程／边界／参考

### 模块 B
…

## 备注
风险、未决、依赖资源、验收标准
```

## 协作与 AI

- 先框架后细节；信任实现方专业，避免微观管理每一行  
- AI 加速草案与变体，创意取舍、情感与架构仍由人定  
- 数值改动一次一条曲线，并说明预期体验变化
